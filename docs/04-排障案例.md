# 04 · 排障案例

做这套工程时真实踩过的坑，每个都按「现象 → 定位 → 根因 → 修复 → 预防」记录。
这部分比配置本身更能说明工程能力：**能不能在信息不足时把范围缩小**。

---

## 案例 1：一条流量策略挂在系统视图，导致整网三层不通

**现象**

核心与接入配置都正常，`display vlan` 里 VLAN 齐全、端口 PVID 正确，但全网终端互相 ping 不通；三台 AP 同时掉线。

**定位过程**

1. 先看 ARP：核心上 `display arp` 只有零星表项，说明三层根本没通；
2. 再看 MAC：`display mac-address` 有表项，说明二层可达 → 问题在二层以上；
3. 比对两台核心的配置差异，发现某台设备上多了一条 `traffic-filter inbound acl 3040`；
4. 关键在于它出现在**系统视图层级**，而不是某个接口下面——这意味着它对该设备所有接口的入方向生效。

**根因**

`traffic-filter` 本意是给 Vlanif40（访客网段）做隔离，结果因为执行时没有先进入接口视图，被挂到了全局。ACL 3040 里是 `deny ip 10.10.40.0/24 → 内网各段`，但挂到全局后所有流量都要过它，其余网段没有 `permit` 兜底，直接全丢。

**修复**

```
interface Vlanif40
  traffic-filter inbound acl 3040
```

同时在系统视图下 `undo traffic-filter inbound acl 3040`，并在 ACL 末尾补 `rule 100 permit ip` 作为兜底。

**预防**

- ACL 末尾**永远留一条 permit**，避免误配导致全阻；
- 挂 `traffic-filter` 一律先 `interface` 再执行，并立刻用 `display current-configuration interface Vlanif40` 确认挂载位置。

## 案例 2：AP 已上线，但 AC 上 VAP 数量为 0

**现象**

`display ap all` 三台 AP 全部 `nor`（正常上线），但 `display vap ssid all` 显示 `Total 0`，STA 搜不到任何 SSID。

**定位过程**

1. `display vap-profile all` 显示两个模板 `Reference` 都是 2，说明模板已绑定到 AP 组；
2. `display ap-group all` 里 `HOSPITAL` 组确实有 3 台 AP；
3. `display radio all` 六个射频全部 `on`，信道与功率正常；
4. 配置数据没问题 → 推断是 **AP 先上线、VAP 模板后添加**，AP 侧没有拿到新配置。

**根因**

eNSP 里的 AP 只在 CAPWAP 建链时拉取一次业务配置，之后 AC 上新增的 VAP 不会主动下发，也不像真机那样有配置同步重试。

**修复**

在 AC 上对 AP 执行复位（或重启 AP 设备），重新建链后 VAP 即下发：

```
ap reset ap-id 1
```

复位后 STA 端 Vap 列表立刻出现 4 条（AP-1 的两个 SSID × 两个射频）。

**预防**

改完无线模板后，统一 `ap reset` 或重启 AP，再用 `display vap ssid all` 确认数量 = AP 数 × 射频数 × SSID 数。

## 案例 3：改了 DHCP 的 DNS，客户端拿到的还是旧地址

**现象**

访客网络终端 `ipconfig` 显示 DNS = `114.114.114.114`，但地址池里已经加过 `dns-list 10.10.200.13`。

**定位过程**

1. `display ip pool name vlan40` 看到 `DNS-Server0 = 114.114.114.114`、`DNS-Server1 = 10.10.200.13`；
2. 说明 `dns-list` 是**追加**语义，不是覆盖——直接再敲一次只是往后加了一个，客户端仍然用第一个。

**修复**

```
ip pool vlan40
  undo dns-list 114.114.114.114
```

（或 `undo dns-list all` 后重新指定。）

修改后客户端重新获取地址，DNS 变为 `10.10.200.13`。

**预防**

改地址池参数前先 `display this`，确认是追加还是覆盖语义；改完让终端 `ipconfig /release` + `/renew` 再看。

## 案例 4：无线能连上，但每次都要输账号密码

**现象**

STA 连接 `HOSPITAL-MED` 时弹出「账户 / 密码」输入框（802.1X 认证框），而不是预共享密钥框；随便填也连不上。

**定位过程**

1. `display vap-profile name MED_VAP` 显示 `Authentication profile: AUTH_MED` —— 模板还挂着 802.1X 认证模板；
2. `display security-profile name MED_WPA2` 显示安全策略仍是 `WPA2 8021X`；
3. 本环境没有 RADIUS 服务器（eNSP 的 Server 设备不提供该服务），802.1X 必然失败。

**修复**

```
security-profile name MED_WPA2
  undo security
  security wpa2 psk pass-phrase <口令> aes

vap-profile name MED_VAP
  undo authentication-profile
```

**踩坑细节**：该版本 VRP 的 `security wpa2 psk` 后面只接受 `hex` / `pass-phrase` 两种关键字，**没有** `cipher` / `simple`；`aes` 要写在口令**之后**。写错会报 `Unrecognized command found at '^' position`。

**预防**

无线配置改完，用两条命令闭环确认：

```
display security-profile name MED_WPA2     →  Security policy: WPA2 PSK
display vap-profile name MED_VAP           →  Authentication profile: 空
```

## 案例 5（平台现象，不是配置错误）

| 现象 | 真实原因 |
|---|---|
| `ping` 网关 `10.10.50.254` 提示 unreachable | VRRP 虚拟 IP 在 eNSP 中不响应 ICMP，业务流量正常 |
| FTP 服务器里只有 README 一个文件 | eNSP 的 FTP 服务只提供 **小于 1MB** 的文件，大文件看不到 |
| 下载的文件出现在 `C:\` 根目录 | Client 设备的「C 盘」映射的就是宿主机磁盘 |
| 设备里 `save` 成功后重开工程配置丢失 | 设备 `save` 只写虚拟 flash，工程要另外 Ctrl+S 才落盘到宿主机 |
